## Лабораторная 10 — ответы
- Сколько компонентных тестов и какие компоненты покрыты: 14 тестов (включая smoke-тест), покрыты компоненты ProductCard, LoginForm и страница Catalog.
- Какие реальные дефекты нашли тесты (label, состояние загрузки и т.п.): Отсутствие связанных `<label>` для полей ввода (ошибки доступности), а также отсутствие корректного отображения состояния загрузки (loading state) в каталоге.
- Покрытие: 98.18% (Lines); хуже всего покрыт LoginForm.jsx (93.33% строк), потому что часть веток валидации с краевыми кейсами (например, неохваченные ошибки сервера) не задействованы в базовых сценариях.
- Время: компонентные 3.48 с, E2E ~25-30 с; во сколько раз медленнее: E2E медленнее примерно в 7-8 раз.
- Что увидели в trace упавшего теста: Пошаговые скриншоты браузера, дерево DOM на момент сбоя и консоль ошибок, позволившая точечно определить упавший селектор.
- Почему E2E не запускаем на каждый PR: Долгое время выполнения (сервер Render может "спать" до минуты) и работа с реальной production-базой данных, что делает проверку неэффективной для каждого промежуточного коммита.
- Сколько e2e-пользователей в базе и чем это плохо: Накапливается много тестовых аккаунтов (с префиксом `e2e+`), «засоряющих» таблицу пользователей в базе данных.
- Использовал(а) ли ИИ и для чего: Да, для настройки окружения Vitest, написания моков fetch и отладки конфигурации Playwright.
